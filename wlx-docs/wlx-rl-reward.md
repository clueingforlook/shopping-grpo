# WLX RL Reward 设计

> 本文记录 ShopSimulator GRPO 阶段的 Reward、步骤级优势和信用分配设计。当前数值作为 Reward v4 第一版，后续通过消融实验调整。

## 1. 总体结构

RL Reward 分成三个板块：

1. **ORM（结果奖励）**：最终买得对不对；
2. **PRM（过程奖励）**：搜索、核验和操作过程是否合理；
3. **信用分配**：把结果或过程奖励分配给真正相关的步骤。

三者不是一回事：ORM 和 PRM 负责“评多少分”，信用分配负责“这些分由哪些步骤承担”。

## 2. ORM：结果奖励

ORM 只评价终局结果，不评价搜索过程。判断依据应来自 ShopSimulator 的最终环境状态和商品数据，不能依赖模型自己声称买了什么。

### 2.1 ShopSimulator 已经记录了什么

可以把一个 ShopSimulator 任务简单理解为四部分：

1. **类目**：用户要买什么类型的商品；
2. **属性**：用户要求商品具有什么特点；
3. **规格**：在目标商品的多个颜色、尺码或容量中，应该选择哪一个；
4. **价格**：最终所选规格是否满足预算。

数据集的设计意图是，用户自然语言中的主要需求基本都落在这四部分中。用户不一定直接照抄结构化字段，例如可能说“浅色系”，而任务隐藏规格记录的是“米色”。这是因为任务先由 Gold 商品构造，再由标注员用同义词或日常表达写成自然语言。

环境同时保存了任务目标和最终购买结果：

```text
任务目标：Gold ASIN + 目标类目 + 目标属性 + 目标规格 + 预算
购买结果：实际 ASIN + 商品类目 + 商品属性 + 已选规格 + 实际价格
```

因此，环境判断 Gold 不需要重新理解用户自然语言，而是直接比较两边的结构化记录：

```text
ASIN 是否相同
目标规格与已选规格是否相同
实际价格是否满足预算
```

命中 Gold ASIN 后，类目和商品级属性来自同一条商品记录，天然一致；真正还需要检查的是 Agent 是否选对该商品下的具体规格，以及该规格的实际价格是否满足预算。

例如用户说“想要浅色系”，任务隐藏答案记录“米色”，商品页面也提供“米色”选项。Agent 最终选择“米色”后，环境比较的是：

```text
目标规格“米色” == 实际选择“米色”
```

它不会在 Reward 阶段重新比较“浅色系”和“米色”，因此这里没有 Eval Rubric 中的同义表达歧义。

这里的“确定性”是指：给定相同的任务记录和购买结果，程序每次都会得到相同结论。它不代表人工标注绝对没有错误。当前数据中任务隐藏属性与 Gold 商品属性一致，但仍可能存在自然语言、目标规格或价格之间的少量标注偏差；这种情况属于数据质量问题，而不是 Reward 比较不稳定。

### 2.2 可以直接规则化

下面这些是结构化、可验证的事实：

- **是否购买**：环境是否执行了 `Buy Now` 并正常结束；
- **商品标识**：最终购买商品的 ASIN；
- **所选规格**：环境保存的 `selected_options`，例如 `尺码=M`；
- **实际价格**：根据商品和所选规格解析出的成交价；
- **预算判断**：在用户预算已被可靠解析、实际价格也可确定时，直接比较 `实际价格 <= 预算上限`；
- **完全一致的规格值**：例如要求 `M`，实际选择也是 `M`；
- **完全一致的规范类别**：任务与商品使用同一套类目 ID 或完全一致的类目路径时，可以直接比较。

这些规则也有边界：

- 如果多条规格轴共同影响价格，而商品数据没有完整的规格组合价格，价格应标记为 `unknown`，不能猜测；
- 规格值只有在含义明确且规范化后完全一致时才能直接判定；
- 类别规则只能证明类目标签是否一致，不能证明两个不同类目在语义上是否兼容。

### 2.3 ORM 第一版分层

ORM 第一版把正常终局分成三类，另外单独处理非模型无效样本：

#### A. 完整 Gold

同时满足下面条件时，Reward 固定为 `1.0`：

```text
实际 ASIN == Gold ASIN
+ 必选规格全部正确
+ 实际价格满足预算
+ 正常完成购买
```

这是唯一的严格成功。命中 Gold ASIN 后，类目和商品级属性来自同一条商品记录，通常天然一致；如果此时属性反而不一致，应优先视为数据或程序异常。

#### B. 已购买，但不是完整 Gold

除完整 Gold 外，所有已购买结果先检查类目，再计算部分分：

```text
类目错误：-0.50

类目正确：
S = 属性满足比例 × 规格满足比例 × 价格是否满足
R_partial = 0.50 × S
```

类目是硬门槛，不能被其他维度补偿。类目正确时，部分奖励范围为 `0～0.50`，不能被记为成功。后续再通过消融实验比较 strict 乘法、loose 加法以及二者混合，不先人为设置品牌、型号等固定权重。

这里不能规定“Gold ASIN 但规格错误”一定高于“错误 ASIN”。例如 Gold ASIN 选择了完全错误的颜色、尺码并且超预算，而另一个商品在四个维度上都很接近需求，后者可以获得更高的部分奖励。ASIN 只决定能否成为完整 Gold，不单独保证部分奖励更高。

#### C. 没有购买

没有最终商品时无法比较四个维度，ORM 统一给予 `-0.25`。这包括主动 `finish_without_purchase`、环境以 `repeat_loop` 终止、达到最大步数，以及模型结束但没有购买。

第一版不根据“是否充分探索后才放弃”设置不同奖励，避免模型为了满足固定搜索次数、候选数量等环境条件而刷分。没有购买比错误类目购买好，但比任何类目正确的购买差。环境故障、数据损坏等非模型原因仍按非模型无效处理并 Mask。

#### D. 非模型无效

环境故障、商品数据损坏或 Reward 无法可靠计算时，将该样本 Mask 掉，不给模型制造奖励或惩罚。

整体层级为：

```text
完整 Gold：1.0
类目正确的部分购买：0～0.50
没有购买：-0.25
购买错误类目：-0.50
非模型无效：Mask
```

### 2.4 ORM 转换为 GRPO 组内优势

同一个任务生成多条轨迹。第 `i` 条轨迹的 ORM 原始分记为 `O_i`，组内平均值和样本标准差分别记为 `μ` 和 `σ`（与 veRL 默认 GRPO 一致）：

```text
A_orm_i = (O_i - μ) / max(σ, 0.1)
A_orm_i = clip(A_orm_i, -2, 2)
```

通俗地说：`A_orm_i` 表示这条轨迹的最终结果比同组其他轨迹好多少或差多少。

分母中的 `max(σ, 0.1)` 表示标准差最小按 `0.1` 计算。这样可以避免组内 ORM 分数非常接近时，把很小的分数差异放大成很强的训练信号。例如 `σ=0.01` 时，实际分母使用 `0.1`；`σ=0.3` 时仍使用 `0.3`。如果整组 ORM 完全相同，分子全部为 0，因此组内 ORM 优势也全部为 0。

`clip(-2, 2)` 用于限制极端优势，避免少量异常组产生过大的梯度。这个标准差下限和截断都属于稳定性设计，需要在实验中记录命中比例；如果它们频繁生效，应重新检查 ORM 分布和阈值。

### 2.5 非 Gold 部分奖励存在语义边界

严格 Gold 判断不需要处理下面这些语义关系。但是，当购买结果不是完整 Gold、Reward 仍想根据相似程度给部分奖励时，就会遇到同义、包含和常识推理问题：

- **模糊颜色**：`浅色系` 与 `米色`、`象牙白`；
- **类别包含关系**：`运动鞋` 与 `跑鞋`；
- **功能要求**：`适合保暖` 与 `羊毛材质`；
- **适用场景**：`适合秋冬`、`适合通勤`；
- **适用人群**：`适合混干皮`、`适合儿童`；
- **风格和主观偏好**：`简约`、`轻便`、`高级感`；
- **近似规格**：`大容量`、`小码`、`约 500ml`；
- **不同表达但含义相同的选项**：`藏青色` 与 `深蓝色`。

如果以后确实要判断有效替代，这类要求可以交给语义 Judge，并至少输出三种状态：

- `satisfied`：证据足够，确认满足；
- `violated`：证据足够，确认违反；
- `unknown`：信息不足或关系不确定。

第一版 Reward v4 不需要因此引入 LLM。非 Gold 的部分奖励只采用保守的结构化信号，并设置较低上限。核心原则是：**字符串没有匹配到，不等于要求被违反。** 无法确定时不奖励，也不把它当成严格 Gold 成功。

### 2.6 当前 ShopSimulator Reward 的实际边界

当前环境确实能直接取得最终商品、已选规格和价格，因此这些事实不需要从模型输出文本中重新识别。

但是，当前 Reward v3 的类别、属性和规格目标部分来自 Gold 商品标注：

- Gold 商品通常容易被规则匹配；
- 合理的替代商品可能因为类目名、属性表达或规格名称不同而被误判；
- 属性比较主要依赖文本出现，不能处理“浅色系包含米色”这样的语义关系。

这些问题影响错误 ASIN 的相似度和有效替代判断，但不影响严格 Gold：只要 ASIN、必选规格、实际价格和购买终局正确，环境就能确定性确认成功。

## 3. PRM：过程奖励

PRM 评价模型如何完成任务，不重复判断最终商品是否满足需求。

这里的一个 `step` 指：模型生成本轮思考和一次工具调用，随后环境返回 observation。PRM 只评价并定位到这个模型动作 step，环境返回内容本身不参与训练。

SFT Eval 的格式正确率为 `100%`，平均 Guard 拒绝只有 `0.05` 次，非法动作仅造成 1 条首要失败，因此第一版不再为 `think`、一般非法调用或工具格式单独设计 PRM。PRM 只针对 SFT 剩余失败中数量较多、并且能够定位的三类事件。

第 `i` 条轨迹、第 `t` 个 step 的过程修正记为 `p_i,t`：

| 过程事件 | `p_i,t` |
| --- | ---: |
| 正常步骤 | `0` |
| 连续无进展后的无效搜索或翻页 | `-0.25` |
| 最终规格选错 | `-0.50` |
| 类目错误、超预算、价格不可验证或必要规格缺失时仍购买 | `-1.00` |

同一步只采用最严重的一条，不累计。第一版不给“打开更多候选”“调用更多工具”“获得新进展”等行为正奖励，避免模型通过增加操作次数刷分。

这些数值不是轨迹总 Reward，而是直接与标准化后的 ORM 优势相加的“步骤优势修正量”。因此，旧方案中的 `-0.02`、`-0.05` 在这里过小，不能直接沿用。

这些信号应尽量来自结构化事件。第一版不让 LLM Judge 给每一个步骤打分，避免训练速度慢、评分不稳定和 Reward hacking。

### 3.1 最终规格选错

环境能够确定最终所选规格是否与任务要求一致。出现可验证的错误规格时：

1. 找到最后一次把该规格设为错误值的 `select_option` step；
2. 只给这个 step `-0.50` 修正；
3. 如果规格轴或选择动作无法可靠定位，则不猜测具体选择步骤，改为惩罚最终 `buy_now` step。

这条规则主要处理 SFT Eval 中数量最多的规格/选项错误。只有比较结果明确为错误时才触发；无法验证时不惩罚。

### 3.2 明确错误的购买决策

模型调用 `buy_now` 后，如果结构化结果明确显示以下任一情况，则给购买 step `-1.00` 修正：

- 商品类目错误；
- 实际价格超预算；
- 完整 variant 的价格不可验证；
- 必要规格没有选择。

错误 ASIN 但类目、规格和价格均合理时，不使用这条 PRM，由 ORM 的部分奖励处理。如果错误规格已经可靠定位并惩罚了对应 `select_option`，同一问题不再在购买 step 重复扣分。

### 3.3 连续无进展后的无效搜索或翻页

ShopSimulator 会在每个环境 step 后记录：

- `runtime_progress_added`：本 step 是否出现环境认可的新结果集、新商品、新信息页、新规格或新约束证据；
- `no_progress_steps`：连续多少个 step 没有出现上述新进展。

这些字段只用于识别持续停滞，不用于发放正奖励：

```text
runtime_progress_added 非空：p_i,t = 0，并由环境清零 no_progress_steps
no_progress_steps < 3：p_i,t = 0
no_progress_steps >= 3，且当前动作是 search_products 或 next_page：p_i,t = -0.25
```

`back_to_search` 不惩罚，因为它通常是下一次搜索所需的正常导航。一次偶然的无进展也不惩罚；只有已经连续停滞后仍执行无效搜索或翻页时，才扣当前 step。环境认可的进展只负责避免误罚，不能带来正分。

PRM 只提供局部修正，不改变 ORM 对最终成功与否的定义。例如过程看起来合理但最终买错，仍然不是成功轨迹。

## 4. 信用分配

信用分配解决的是：一条长轨迹最后得到奖励后，究竟应该奖励或惩罚哪些步骤。

### 4.1 下标含义

```text
i：同一任务 rollout 组中的第几条轨迹
t：该轨迹中的第几个 agent step
k：该 step 中的第几个模型生成 token
```

例如 `A_3,5,20` 表示第 3 条轨迹、第 5 个 step、第 20 个模型 token 的优势。

### 4.2 计算步骤优势

每个 step 先继承所在轨迹的 ORM 组内优势，再加上只属于自己的 PRM 修正：

```text
A_i,t = A_orm_i + p_i,t
```

因此，重复搜索的惩罚只改变重复搜索 step，不会加到其他正常 step 上。不同轨迹相同编号的 step 可能执行完全不同的动作，所以 PRM 不在“相同 step 位置”之间做组内中心化。

轻微过程问题只削弱该 step 的训练信号。对于可验证的错误规格选择，使用：

```text
A_i,t = min(A_orm_i + p_i,t, -0.25)
```

对于类目错误、超预算、价格不可验证或必要规格缺失时仍购买，使用更强的负向下限：

```text
A_i,t = min(A_orm_i + p_i,t, -0.50)
```

`min` 保证这些确定错误的 step 不会因为整条轨迹的 ORM 优势较高而仍获得正向强化。连续无进展规则不使用强制负向下限，只按 `A_orm_i - 0.25` 轻微削弱，因为环境的进展判定仍然是一种启发式规则。

### 4.3 Step-LATA：按 step 长度调整训练力度

PRM 决定 step 好不好；Step-LATA 只处理不同 step 的模型 token 数量不同造成的训练力度差异。

设第 `i` 条轨迹第 `t` 个 step 的模型生成长度为 `L_i,t`，参考长度为 `L_ref`：

```text
w_i,t = clip(sqrt(L_ref / L_i,t), 0.5, 2.0)
A_i,t,k = clip(A_i,t * w_i,t, -2, 2)
```

含义如下：

- step 长度等于 `L_ref`：权重为 `1`，不改变优势；
- step 比 `L_ref` 短：单个 token 权重适当提高；
- step 比 `L_ref` 长：单个 token 权重适当降低；
- 权重限制在 `0.5～2.0`，避免极短或极长 step 得到极端权重。

例如 `L_ref=64`：

| 当前 step 长度 | 长度权重 |
| ---: | ---: |
| 16 | `2.0` |
| 64 | `1.0` |
| 256 | `0.5` |

使用 `sqrt(L_ref/L)` 而不是直接使用 `1/sqrt(L)`，是为了只调整长短 step 的相对影响，而不把所有优势整体缩小。这里的 Step-LATA 是针对明确 agent step 边界的长度调整版本，不负责判断步骤对错，也不代替 PRM。

### 4.4 `L_ref` 的确定方法

在正式 RL 前，用 SFT 模型和正式训练 tokenizer 跑一批有代表性的 rollout：

1. 只统计每个 step 中模型生成的思考、回答和工具调用 token；
2. 不统计 system、user 和环境 observation token；
3. 收集至少数千个 step；
4. 取所有 step 长度的中位数作为 `L_ref`；
5. 整个实验固定该值，不随 batch 动态改变。

例如 step 长度中位数为 72，就设置 `L_ref=72`。使用中位数是为了避免少量特别长的 step 把参考长度拉高。

最终，GRPO loss 只使用模型生成 token 对应的 `A_i,t,k`；工具和环境 observation token 全部 Mask。ORM 提供整条轨迹的相对方向，PRM 只修正对应 step，Step-LATA 再调整该 step 内每个 token 的训练权重。

## 5. 当前结论

- ORM 第一版以严格 Gold 为目标，使用确定性规则，不引入在线 LLM Judge；
- Gold 成功要求实际 ASIN、必选规格、实际价格和购买终局均正确，奖励为 `1.0`；
- 类目错误购买为 `-0.50`；类目正确时按属性、规格和价格的 strict 乘积计算部分分，范围为 `0～0.50`；
- ASIN 正确不保证部分分更高，ASIN 只决定能否成为完整 Gold；
- 所有模型导致的未购买终局统一使用 ORM `-0.25`，不按搜索次数或候选数量区别奖励；
- 语义要求不能因为字符串不匹配就判为违反，也不能被判成严格 Gold；
- ORM 使用 `max(σ, 0.1)` 计算稳定的组内优势，并截断到 `-2～2`；
- PRM 第一版只处理错误规格选择、明确错误购买，以及连续无进展后的无效搜索/翻页；
- 普通 step 使用 `A_i,t = A_orm_i + p_i,t`；错误规格 step 的优势不高于 `-0.25`，明确错误购买 step 的优势不高于 `-0.50`；
- 当前主训练关闭 Step-LATA：SFT 轨迹的 step 基本只是短工具调用，长度不能可靠代表推理量；
