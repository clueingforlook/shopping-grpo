# Eval v2：评测说明

## 这版解决了什么

Eval v2 用同一批 200 个任务比较 Base、SFT 和后续 RL。它把三件事分开报告：

1. **客观结果**：工具格式、动作是否合法、是否购买，以及环境验证器如何判断商品；
2. **需求满足**：最终购买商品是否满足用户原始需求；
3. **执行过程**：搜索、候选利用、证据核验、购买决策和终止效率。

旧版本曾用字符串规则判断部分自然语言需求，容易把“米色—浅色系”等语义关系判错。Eval v2 不再设置确定性 Rubric：程序只提取客观事实，全部用户需求统一交给校准后的 `deepseek-v4-pro` 判断。

## 完整流程

1. Harness 保存 Base/SFT 与 ShopSimulator 交互的完整轨迹。
2. Rule Gate 检查工具 Schema、Guard 拒绝、非法动作、循环、截断、终止和服务异常。
3. 环境结果验证器独立报告目标商品、有效替代、部分符合、错误购买或未购买。
4. 冻结 Rubric 将每个任务拆成独立的硬性要求和软性偏好。
5. V4 Pro 只根据用户需求和模型当时可见的轨迹，判断全部 Rubric，并给五项过程能力打 0–2 分。
6. 程序合并三类结果，生成逐轨迹记录、单模型汇总、复核队列和 Base/SFT 成对比较。

已有轨迹可以反复离线评测；本次没有重新运行 Base、SFT 或环境。

## 程序与 LLM 的边界

| 模块 | 负责内容 |
|---|---|
| Rule Gate | 格式、动作合法性、Guard、循环、终止、上下文和服务异常 |
| 环境验证器 | 是否购买、实际商品和选项、是否命中目标或有效替代 |
| Rubric Judge | 最终购买商品是否满足每一条用户要求 |
| Process Judge | 搜索策略、候选利用、证据核验、购买决策和终止效率 |
| 人工复核 | 环境与 Judge 冲突、证据不足、低置信度或责任不清 |

Rubric 只评价最终购买商品。没有购买时，候选商品即使看起来符合要求，也不能记为 `satisfied`，相应要求记为 `unknown`。`available_options` 只表示存在某个选项，只有 `selected_options` 才代表模型实际选择。

## 五项过程指标

| 中文名称 | 程序字段 | 2 分 | 1 分 | 0 分 |
|---|---|---|---|---|
| 搜索策略 | `search_strategy` | 直接命中强候选或有效收敛 | 方向正确但命中、覆盖或调整有限 | 搜索无关或持续无效 |
| 候选利用 | `candidate_utilization` | 充分利用强候选 | 看过相关候选但利用不足 | 忽略强候选或主要查看无关商品 |
| 证据核验 | `evidence_verification` | 可见信息覆盖关键要求 | 只确认了部分要求 | 基本没有关键证据 |
| 购买决策 | `decision_quality` | 购买或放弃与充分证据一致 | 决定有依据但证据不完整 | 错购、错过强候选或被动耗尽 |
| 终止效率 | `termination_efficiency` | 证据充分后及时正确结束 | 正确结束但有冗余 | 过早购买、循环、非法动作或耗尽预算 |

“核验”指价格、属性、规格或选项真实出现在模型可见的 Observation 中；不要求模型显式写出思考，也不能用模型自己的口头声明代替页面证据。

## Judge 校准

Gold v6 包含 24 条轨迹、182 条 Rubric，需求覆盖率为 100%。V4 Pro 的冻结校准结果为：

| 校准项 | 一致率 | 门槛 |
|---|---:|---:|
| 五项过程分精确一致 | 84.2% | 75% |
| Rubric 状态精确一致 | 95.6% | 80% |
| 责任归因一致 | 95.8% | 80% |
| 首要失败一致 | 70.8% | 70% |

五项中的证据核验单项一致率只有 62.5%，说明细粒度过程分仍有噪声。它适合做诊断和抽样分析，不应未经进一步验证就直接变成 RL Reward。
