# WLX Base 与 SFT：200 任务最终结果

## 一句话结论

SFT 的主要收益不是学会工具调用格式，而是学会把搜索结果继续执行成一次有效购买：查看候选、核对商品、选择规格、购买并及时结束。

| 指标 | Base | SFT |
|---|---:|---:|
| 格式正确 | 196/200（98.0%） | 200/200（100%） |
| 全部样本购买正确 | 3/200（1.5%） | 118/200（59.0%） |
| 可比较有效样本购买正确 | 3/197（1.52%） | 114/184（61.96%） |
| 平均输入 Token 总量 | 62,836 | 44,531 |
| 平均 Guard 拒绝次数 | 3.625 | 0.050 |
| 平均搜索次数 | 2.130 | 1.345 |

181 对可干净比较的同任务轨迹中：SFT 独自成功 109 对，两者都成功 3 对，两者都失败 69 对。其余 19 对存在非模型无效、验证器冲突或结果不可验证，不计入干净的成败转移。

## Rubric 需求满足结果

> **暂定结果：** 本节混入了当前 Eval v1 的确定性 Rubric 判断，其中已发现语义等价误判。全部 Rubric 由校准后的 LLM 重新判断前，本节数字只用于暴露问题，不用于 Reward 或正式结论。

200 个任务的 Rubric 共拆出 1,428 条用户要求，其中硬性要求 1,157 条、软性偏好 271 条。下面统计最终购买商品对这些要求的满足情况。若模型没有购买，整条任务会在结果层明确记为“未购买”（`no_purchase`）；但因为不存在最终商品，无法继续判断它的颜色、规格等单项要求，所以这些 Rubric 项记为“未知”。若模型已经购买，但轨迹中的商品页面没有提供某项属性的证据，例如用户要求“环保无异味”，页面却没有相关描述，该项也记为“未知”，而不是在没有反证的情况下判为“违反”。

| 要求范围 | 模型 | 满足 | 违反 | 未知 | 冲突 |
|---|---|---:|---:|---:|---:|
| 全部要求（1,428 条） | Base | 23（1.61%） | 0 | 1,405（98.39%） | 0 |
| 全部要求（1,428 条） | SFT | 1,081（75.70%） | 43（3.01%） | 304（21.29%） | 0 |
| 硬性要求（1,157 条） | Base | 16（1.38%） | 0 | 1,141（98.62%） | 0 |
| 硬性要求（1,157 条） | SFT | 885（76.49%） | 37（3.20%） | 235（20.31%） | 0 |
| 软性偏好（271 条） | Base | 7（2.58%） | 0 | 264（97.42%） | 0 |
| 软性偏好（271 条） | SFT | 196（72.32%） | 6（2.21%） | 69（25.46%） | 0 |

按完整任务计算，Base 只有 3/200 个任务满足全部硬性要求；SFT 为 115/200（57.5%）。同时满足任务中全部硬性要求和软性偏好的，Base 为 3/200，SFT 为 107/200（53.5%）。

### 同一条要求的变化

Base 中 1,405 条状态为“未知”的要求，在 SFT 中有：

- 1,058 条变为满足（75.30%）；
- 43 条变为明确违反（3.06%）；
- 304 条仍然未知（21.64%）。

另外 23 条 Base 已满足的要求，在 SFT 中仍全部满足。也就是说，SFT 的主要变化是完成购买后让大量原本无法验证的需求变得可验证且满足，而不是简单把“违反”修成“满足”。

### 不同类型要求的表现

SFT 对明确、结构化要求的满足率较高：品牌 18/20（90.0%）、商品类别 142/164（86.6%）、预算 159/192（82.8%）、数量 40/51（78.4%）。功能要求为 189/250（75.6%），规格选项为 32/45（71.1%），一般属性为 440/603（73.0%）。

偏好类要求只有 50/86（58.1%）被确认满足，明显低于品牌、类别和预算。这部分包含风格、品质、用途适配等模糊要求，商品页面经常没有充分证据，因此不能简单把剩余部分全部解释为模型选错。这里的“偏好类”指 Rubric 中 `type=preference` 的条目，不等同于前文按优先级统计的全部软性要求（`priority=soft`）。

上面的数字按 Rubric 条目计数。同一任务如果包含 3 条一般属性要求，就会计为 3 条。为了避免需求较多的任务权重更大，下面再按“任务×要求类型”统计：每个任务在一种类型下最多计一次；该类型的所有要求都满足才记为“全部满足”，只要有一条明确违反就记为“存在违反”，其余记为“未能全部确认”。

任务级统计比条目级统计更严格。例如 SFT 满足了 440/603 条一般属性，但只有 112/187 个相关任务满足了该任务中的全部一般属性。它说明模型经常能满足一部分属性，却仍遗漏同一任务中的其他属性。品牌、类别和预算依旧最好；偏好、一般属性和功能要求仍是主要短板。

### 结果分析

Rubric 结果与购买成功率给出的结论一致，但信息更细：SFT 已经能满足大部分用户要求，剩余问题主要有两类。一类是 43 条有明确反证的要求，说明确实选错属性、超预算或买错类别；另一类是 304 条未知要求，表示没有购买成功，或轨迹中的商品证据不足。设计 Reward 时，明确违反可以作为较可靠的负信号；未知不能直接按违反惩罚，应结合是否购买、是否充分核验和是否为环境信息缺失处理。

## 五项过程能力

每项 0–2 分，越高越好。

| 中文指标（程序字段） | Base | SFT | 变化 |
|---|---:|---:|---:|
| 搜索策略（`search_strategy`） | 1.845 | 1.920 | +0.075 |
| 候选利用（`candidate_utilization`） | 0.890 | 1.665 | +0.775 |
| 证据核验（`evidence_verification`） | 0.755 | 1.415 | +0.660 |
| 购买决策（`decision_quality`） | 0.450 | 1.425 | +0.975 |
| 终止效率（`termination_efficiency`） | 0.055 | 1.645 | +1.590 |

Base 原本通常能构造合理搜索词，因此“搜索策略”提升不大。真正的大幅提升来自终止效率、购买决策、候选利用和证据核验。

## SFT 还失败在哪里

Base 的主要失败是非法动作（`invalid_action`，130 条）和重复循环无进展（`repeat_loop_no_progress`，57 条）。

SFT 中 118 条没有识别到模型失败；剩余主要问题是：

- 规格/选项错误（`wrong_option_selection`）：44；
- 重复循环无进展（`repeat_loop_no_progress`）：11；
- 超预算购买（`over_budget_purchase`）：10；
- 核验不足（`insufficient_verification`）：7；
- 过早购买（`premature_purchase`）：6；
- 动作或上下文预算耗尽（`context_or_action_budget_exhausted`）：3；
- 非法动作（`invalid_action`）：1。

因此后续 RL 应优先处理规格选择、预算约束、购买前核验和动作失败后的恢复；格式只需作为基础门槛，不应成为主要优化目标。

## 可信度边界

过程 Judge 使用 `deepseek-v4-flash`、冻结 Rubric 和盲评 Prompt v2。24 条人工 Gold 校准中：五维分数完全一致率 80.83%，需求状态一致率 95.92%，责任归因一致率 95.83%，第一失败原因一致率 70.83%，均通过预设门槛。

这证明当前 Eval 技术链路基本受控，但不等于独立 Judge 泛化精度：Gold 和 Prompt 都参与过开发。正式论文结论应增加一批未参与调参的新人工 Gold Set。

复核队列为 Base 195 条、SFT 80 条。它主要影响细粒度语义归因，不改变确定性的格式和购买结果。把失败原因用于 Reward 前，应优先抽查相关样本。
