# WLX Eval v2：Base 与 SFT 最终结果

## 一句话结论

SFT 把购买正确率从 1.5% 提升到 59.0%。它学到的主要不是 JSON 或工具调用格式，而是围绕强候选继续选择规格、购买并结束任务；剩余失败主要集中在规格选择、预算和购买前核验。

## 核心结果

| 指标 | Base | SFT |
|---|---:|---:|
| 格式正确 | 196/200（98.0%） | 200/200（100%） |
| 全部任务购买正确 | 3/200（1.5%） | 118/200（59.0%） |
| 可直接评价任务购买正确 | 3/197（1.5%） | 114/184（62.0%） |
| 非模型无效 | 3 | 0 |
| 评测资格需复核 | 0 | 16 |
| 最终复核队列 | 8/200（4.0%） | 52/200（26.0%） |

181 对可以干净比较的同任务轨迹中，两者都成功 3 对、只有 SFT 成功 109 对、两者都失败 69 对；另外 19 对因非模型无效、验证冲突或不可验证而不进入干净转移统计。

## 购买结果分布

| 结果 | Base | SFT |
|---|---:|---:|
| 目标商品购买成功 | 3 | 117 |
| 有效替代商品 | 0 | 1 |
| 部分符合 | 0 | 48 |
| 错误购买 | 0 | 8 |
| 无法验证 | 0 | 11 |
| 未购买 | 197 | 15 |

SFT 的进步首先表现为“能够完成购买”。但 48 条部分符合说明，完成购买不等于满足全部规格。

## 用户需求满足情况

200 个任务共包含 1,428 条 Rubric，其中硬性要求 1,157 条、软性偏好 271 条。

| 范围 | 模型 | 满足 | 违反 | 未知 |
|---|---|---:|---:|---:|
| 全部要求 | Base | 23（1.6%） | 0 | 1,405（98.4%） |
| 全部要求 | SFT | 1,112（77.9%） | 46（3.2%） | 270（18.9%） |
| 硬性要求 | Base | 16（1.4%） | 0 | 1,141（98.6%） |
| 硬性要求 | SFT | 910（78.7%） | 34（2.9%） | 213（18.4%） |
| 软性偏好 | Base | 7（2.6%） | 0 | 264（97.4%） |
| 软性偏好 | SFT | 202（74.5%） | 12（4.4%） | 57（21.0%） |

按完整任务统计，SFT 有 118/200 个任务满足全部硬性要求，110/200 个任务满足全部硬性要求和软性偏好。Base 两项均为 3/200。

Base 的 1,405 条未知要求，在 SFT 中有 1,089 条变为满足、46 条变为明确违反、270 条仍未知。这说明 SFT 的主要变化是完成购买后，让原本无法判断的需求获得了可见结果。

| 数量 | 49 | 39（79.6%） | 2 | 8 |

类别和预算相对稳定；一般属性、功能、规格选项和偏好仍有较多未知或违反。

## 五项过程能力

每项 0–2 分，表中为 200 条轨迹的平均分。

| 中文指标（程序字段） | Base | SFT | 变化 |
|---|---:|---:|---:|
| 搜索策略（`search_strategy`） | 1.270 | 1.810 | +0.540 |
| 候选利用（`candidate_utilization`） | 0.800 | 1.635 | +0.835 |
| 证据核验（`evidence_verification`） | 0.600 | 1.405 | +0.805 |
| 购买决策（`decision_quality`） | 0.045 | 1.295 | +1.250 |
| 终止效率（`termination_efficiency`） | 0.030 | 1.370 | +1.340 |

成对比较中，SFT 在终止效率上改善 145 条、购买决策改善 142 条、候选利用改善 147 条。最大的提升发生在“把搜索继续执行成正确购买”，而不是格式。

## 行为变化

| 行为指标 | Base | SFT |
|---|---:|---:|
| 平均尝试工具调用 | 9.640 | 8.295 |
| 平均成功执行工具调用 | 5.995 | 8.245 |
| 平均 Guard 拒绝 | 3.625 | 0.050 |
| 平均搜索次数 | 2.130 | 1.345 |
| 平均购买调用次数 | 0.045 | 0.925 |
| 平均输入 Token 总量 | 62,836 | 44,531 |

SFT 尝试动作更少，但真正执行的动作更多，Guard 拒绝几乎消失，同时更经常完成购买。

## SFT 剩余失败

| 首要失败 | 数量 |
|---|---:|
| 规格/选项错误（`wrong_option_selection`） | 44 |
| 重复循环无进展（`repeat_loop_no_progress`） | 11 |
| 超预算购买（`over_budget_purchase`） | 10 |
| 核验不足（`insufficient_verification`） | 6 |
| 过早购买（`premature_purchase`） | 5 |
| 动作或上下文预算耗尽 | 3 |
| 非法动作 | 1 |
| 商品选择错误（`wrong_product_selection`） | 1 |
| 未识别到模型失败（`none`） | 119 |

后续 RL 最值得优先处理的是：最终规格是否正确、是否超预算、购买前是否确认关键硬要求，以及失败后能否恢复而不是循环。

## 结果的可信度边界

Eval v2 同时保留环境结果和 LLM Rubric，二者不会互相覆盖。SFT 中有 23 条轨迹被环境判为购买不正确，但 Judge 认为全部硬性要求满足；另有 21 条环境购买正确，但可见证据仍不足以确认全部硬要求。这些样本可能包含有效替代、环境 Goal 过严、页面证据不足或 Judge 误判，应进入人工抽查，不能直接拿某一方当绝对真值。

V4 Pro 校准整体通过，但证据核验单项只有 62.5% 一致率；因此过程指标适合指导失败分析，暂不建议原样作为 Reward。
