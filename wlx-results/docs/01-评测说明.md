# WLX Eval：评测说明

## 目的

这套 Eval 用同一批 200 个任务比较 Base、SFT 和后续 RL。它回答四件事：

1. 工具调用格式是否正确；
2. 是否买到满足需求的商品；
3. 搜索、核验、选择和结束过程哪里做得好或不好；
4. 失败来自模型，还是环境、Harness、任务数据或验证器。

Eval 用于测量和诊断；Reward 是 RL 训练时的信号。可靠的确定性结果可以同时用于二者，但不会直接把整套 Eval 压成一个 Reward。

## 评测流程

1. Harness 运行模型与 ShopSimulator，保存完整轨迹。
2. 程序检查轨迹是否可评价，排除明确的非模型故障。
3. 程序判断格式、动作合法性、购买终局和行为次数等确定性事实。
4. 冻结 Rubric 将用户需求拆成可逐条检查的硬性要求和软性偏好。
5. 经人工 Gold Set 校准的 DeepSeek V4 Pro Judge 逐条评价全部 Rubric，并评价五个过程维度。
6. 程序定位第一处关键失败，生成单模型汇总和 Base/SFT 成对比较。

## 两类指标

### 确定性指标

程序可以直接从轨迹和环境事实中判断：

- 格式是否正确；
- 是否购买；
- 环境验证器判定为目标商品、有效替代、部分匹配还是错误商品；
- 实际购买商品的 ASIN、价格和所选选项等终局事实；
- 搜索、查看、重复动作、非法动作、步数和终止类型。

### Rubric 与语义过程指标

用户自然语言 Rubric 的满足情况由校准后的 LLM Judge 逐条判断，输出 `satisfied / violated / unknown / conflicting`、理由、证据事件 ID 和置信度。程序提供客观轨迹和终局事实，但不直接决定 Rubric 状态。

同一个 Judge 另外评价五项过程能力：

| 中文名称 | 程序字段 | 判断内容 |
|---|---|---|
| 搜索策略 | `search_strategy` | 搜索词是否覆盖核心需求，失败后是否有效调整 |
| 候选利用 | `candidate_utilization` | 是否查看、比较和继续利用高匹配候选 |
| 证据核验 | `evidence_verification` | 购买前是否核对价格、属性、规格和选项 |
| 购买决策 | `decision_quality` | 购买或放弃是否建立在充分证据上 |
| 终止效率 | `termination_efficiency` | 是否及时购买/停止，是否避免循环和预算耗尽 |

每项单独报告 0–2 分，不简单求和。`2` 表现好，`1` 有明显不足，`0` 存在关键错误。

## 常见结果和失败名称

| 中文名称 | 程序字段 | 含义 |
|---|---|---|
| 目标商品购买成功 | `gold_purchase` | 买到任务参考商品且规格有效 |
| 有效替代商品 | `valid_alternative_purchase` | 不是参考商品，但满足用户实际要求 |
| 部分符合 | `partial_purchase` | 商品只满足部分要求 |
| 错误购买 | `wrong_purchase` | 已购买，但关键要求不满足 |
| 未购买 | `no_purchase` | 轨迹结束时没有购买 |
| 无法验证 | `unverifiable` | 现有证据不足以可靠判断 |
| 规格/选项错误 | `wrong_option_selection` | 商品方向可能对，但颜色、尺码等选错 |
| 超预算购买 | `over_budget_purchase` | 最终价格违反预算要求 |
| 核验不足 | `insufficient_verification` | 购买前没有核对关键证据 |
| 过早购买 | `premature_purchase` | 尚未取得充分证据便购买 |
| 重复循环无进展 | `repeat_loop_no_progress` | 重复搜索或操作但没有推进任务 |
| 非法动作 | `invalid_action` | 调用了当前状态下不可执行的动作 |
| 动作/上下文耗尽 | `context_or_action_budget_exhausted` | 未完成任务便耗尽允许的资源 |
| 无模型失败 | `none` | 没有识别到模型侧关键失败 |

## Eval v2 当前状态

- Base 和 SFT 各 200 条完整轨迹已保存。
- 200 个任务的 Rubric 已冻结。
- 24 条 Gold 轨迹中的 182 条 Rubric 已按 Eval v2 口径完整复核，覆盖率为 100%。
- Eval v2 已改为由 `deepseek-v4-pro` 判断全部 Rubric，不再用字符串规则给需求下结论。
- 旧版 Base/SFT 共 400 条结果仍保留；Eval v2 需要先重新校准 V4 Pro，再离线重评这 400 条轨迹。
- 不需要重新运行模型即可基于现有轨迹修改指标并离线重评。

当前 200 条任务参与过评测开发，应视为开发评测集（dev-eval）。后续报告最终 RL 效果时，还应冻结一批未参与 Reward 和规则设计的新任务。
